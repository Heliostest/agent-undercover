# 发言含混 + 卧底伪装 — 设计文档

日期：2026-09-21  
仓库：https://github.com/Heliostest/agent-undercover  
状态：已与产品方对齐，待实现计划

## 1. 目标

根据最近两局（奶茶/咖啡、泡面/外卖）复盘：

1. **发言含混**：降低整桌挤同一生活场景的概率，首轮四人从不同「角度」开口。
2. **卧底伪装**：当 agent 在 thought 中判断自己可能是少数时，speech 优先贴多数人已用的说法框架，禁止再抛只属于本词的独特点（如「送上门」vs「自己冲」）。

方案：**提示词加强 + 轻量 `speechAngle` 机制**（方案 A）。

## 2. 非目标

- 强制第二轮发言 / 首轮禁止投票
- 用规则引擎判定「有没有讲对角度」
- 改词库、人设、投票规则、计票与出局逻辑
- 公开时间线或 SSE 暴露 `speechAngle`
- 新增「是否卧底」服务端状态机（伪装只靠 prompt，不靠上帝视角身份注入）

## 3. 机制与数据流

### 3.1 角度池（服务端常量）

| id | label | hint（写入 prompt） |
|----|-------|---------------------|
| `feel` | 感受/心情 | 身体或心情上的一点感觉 |
| `timing` | 时机/场合 | 什么时候会想到它 |
| `habit` | 个人小习惯 | 一个很小的个人习惯 |
| `object` | 相关的人或物 | 相关的人或物（不说词本身） |

### 3.2 分配时机

- 每位**存活**玩家**每次发言前**，服务端为该座位抽取本轮 `speechAngle`。
- 同一发言轮次内四人**尽量不重复**；存活不足 4 或不重复不够时允许重复。
- 仅用于构建 speech prompt；**不写入**公开 `log` / SSE 事件；其他座位不可见。

### 3.3 视图字段

`AgentView`（`lib/game/types.ts`）增加可选字段：

```ts
speechAngle?: {
  id: 'feel' | 'timing' | 'habit' | 'object';
  label: string;
  hint: string;
};
```

由会话/裁判在调用 `PlayerAgent.speak` 前注入；`buildSpeechMessages` 读到则追加硬约束。

### 3.4 校验

维持现有：合法 JSON、`speech` 非空、公开 `speech`/`reason` 不漏词面。  
**不**对角度做结构化校验。

### 3.5 卧底伪装（机制侧）

不新增身份状态。伪装完全由 prompt 驱动：若 thought 判断自己可能是少数，speech 贴多数说法并避开独特点；`speechAngle` 照常注入，避免为了伪装又挤回同一场景。

## 4. 提示词改动（`lib/agents/prompt.ts`）

### 4.1 `speechStrategy`

- 首轮：在现有「先藏一点」之上，明确不要与已发言者挤同一生活场景；用分配到的角度另开一条线。
- 有前人发言后：
  - 同边共鸣：认方向即可，换角度补一句，禁止复述场景。
  - 若自觉可能是少数：公开发言优先借用多数人已用的说法框架，只改成自己的角度；禁止再抛只属于自己词的独特点。

### 4.2 `thoughtPlan`

有前人时顺序改为：

1. 谁像同一边 / 谁对不上  
2. **一句「我是否可能是少数」**  
3. 本轮怎么说、藏什么  

若判断可能是少数：thought 写清「伪装策略：贴谁的说法、避开哪个独特点」。

### 4.3 `speechAngle` 硬约束（有字段才追加）

> 本轮你的发言角度是「{label}」：{hint}。speech 必须落在这个角度；不要改聊别人已经占满的同一场景。thought 里可以提及其他角度，但 speech 只走这一条。

### 4.4 投票 prompt

仅追加一句：

> 不要只因为对方没复述你熟悉的那个场景就投票；先看他的细节是否和你的词相容。

### 4.5 不改

人设 `systemPrompt`、漏词校验结构、JSON 输出格式（`thought` + `speech` / `vote` + `reason`）。

## 5. 主要改动面

| 模块 | 职责 |
|------|------|
| `lib/game/types.ts` | `AgentView.speechAngle?` |
| 角度分配工具（新或放 `lib/game/`） | 常量池 + 本轮去重抽取 |
| 会话 / 裁判发言路径 | speak 前注入 `speechAngle` |
| `lib/agents/prompt.ts` | strategy / thoughtPlan / angle 硬约束 / 投票一句 |
| 测试 | 分配、prompt 含文案、公开事件无 angle 字段 |

## 6. 测试与验收

### 6.1 单测

1. 一轮 4 人角度尽量不重复；仅 2 人存活允许重复；公开 log/SSE **不含** `speechAngle`。  
2. `buildSpeechMessages`：有 angle 时含 label/hint；无字段时与现行为一致。  
3. 有前人发言时 prompt 含「是否可能是少数」「禁止挤同一场景」；投票 prompt 含场景相关那句。  
4. 既有漏词 / JSON 解析测试保持通过。

### 6.2 手工验收（OmniRoute 1～2 局）

- 首轮四人场景明显岔开。  
- 若某人 thought 认少数：speech 不再抛「送上门 / 自己冲」类硬伤。  
- 不保证多轮；公开发言辨识度应下降；上帝视角 thought 仍可读。

## 7. 风险

- 模型仍可能无视角度提示 → 靠注入 + 文案强调，不靠规则引擎硬判。  
- 角度 hint 过窄可能导致发言空洞 → hint 保持生活向、可迭代文案。  
- 与未提交的 OmniRoute 模型过滤改动无关，本 spec 独立实现。
